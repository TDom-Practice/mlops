# Інтеграційна записка: ContractPilot AI

## Моя легенда

**ContractPilot AI** — B2B legal-tech SaaS для юридичних і закупівельних команд середнього бізнесу в ЄС та США. Платформа обслуговує 1 200 корпоративних клієнтів, має ARR $21,6M і обробляє 5,4M запитів на місяць. Вона поєднує LLM для пояснення умов договорів, ML-модель для пріоритизації ризиків і RAG для пошуку в ізольованих базах знань клієнтів (4,2M векторів).

Підставою для створення фінального пакета став інцидент у вересні 2026 року: LLM неправильно інтерпретувала умову автоматичного продовження договору. Компанія надала клієнту service credit на $45K, а клієнт призупинив розширення співпраці на $120K ARR. Рада директорів дозволила продовжити запуск за умови впровадження контрольованих релізів, ізоляції даних клієнтів і прозорого управління витратами MLOps.

## Інтеграція матеріалів попередніх ДЗ

| Попередня тема | Що використано у фінальному проєкті |
|---|---|
| **ДЗ 1 · Containerization** | Вимоги до фіксації версій залежностей, `.dockerignore`, перевірок безпеки, походження model artifacts, Model Card і SBOM. Для ContractPilot також визначено контроль галюцинацій, prompt injection і версій prompt templates. |
| **ДЗ 2 · Kubernetes** | Рекомендації щодо EKS, розділення production і non-production середовищ, RBAC, ResourceQuota, NetworkPolicy, HPA, моніторингу та rollback. Для ContractPilot додано tenant-aware API gateway і контроль доступу до RAG. |
| **ДЗ 3 · GitOps** | Git як єдине джерело конфігурації, перевірка pull/merge requests, Argo CD, drift detection і rollback. Додатково визначено підписування комітів, release gates та Canary 5% → 20% → 50% → 100%. |
| **ДЗ 4 · Моніторинг** | Підхід до оцінювання моделей на основі узгоджених метрик, експериментів і підтверджувальних матеріалів. Для ContractPilot визначено стек Prometheus/Grafana/Loki та метрики якості, retrieval deny rate, prompt injection, галюцинацій і вартості запиту. |
| **ДЗ 5 · Training pipeline** | Концепцію GitLab CI → AWS Step Functions, Data Validation, фіксацію commit SHA, версій даних і конфігурації моделі, логування в MLflow та ручне погодження перед production. Для ContractPilot додано юридичні, мовні, adversarial- і RAG-перевірки, а також зв'язок між Model Registry і Canary-релізом. |

## Що додано для фінального проєкту

1. **П'ять ADR** із обґрунтуванням архітектурних рішень і фінансових компромісів.
2. **Threat Model** із 18 загрозами, матрицею пріоритетів 3×3, оцінкою впливу та відповідальними ролями.
3. **Release Checklist** із критеріями допуску для LLM, ML, RAG, безпеки та регуляторної відповідності.
4. **Incident Runbook** із трьома сценаріями інцидентів, порядком реагування, часовими межами та правилами комунікації.
5. **Business Justification** із трирічним TCO, Unit Economics, ROI та аналізом альтернатив.
6. **Stakeholder Presentation** на 15 слайдів для представлення рішення раді директорів.

## Межі використання попередніх матеріалів

Матеріали попередніх ДЗ використовувалися як основа для вимог, архітектурних рішень і управлінських процесів. Вони не підтверджували наявність готової production-інфраструктури, контейнерів, EKS, GitOps або робочого training pipeline. Реалізацію цільової архітектури ContractPilot AI, фінансову модель, заходи безпеки та процеси управління розроблено окремо в межах фінального проєкту.
